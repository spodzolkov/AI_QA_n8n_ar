# Скіл першого запуску проєкту (`init`)

Використовуйте цей скіл, коли користувач уперше відкрив або клонував репозиторій, викликав `init` / `/init`, або попросив розгорнути й налаштувати проєкт під свій агентський харнес та сервер **n8n**.

> **Важливо**: Проводьте користувача через стадії послідовно, ввічливо та українською мовою. Ніколи не виводьте значення `N8N_API_KEY` відкритим текстом у відповідях чату.

---

## Стадія 1. Перевірка середовища та встановлення залежностей

1. Перевірте наявність середовища виконання у терміналі:
   - `node -v` (потрібна версія Node.js `>= 20`) та `npm -v`.
2. Перевірте, чи встановлені пакети в `node_modules/`. Якщо папки `node_modules` немає або відсутній `node_modules/n8n-mcp`:
   - Виконайте `npm install`.
3. Скомпілюйте TypeScript-код MCP-серверів та лаунчера:
   - Виконайте `npm run build` і переконайтеся, що з'явилися файли `dist/mcp/doc-server.js` та `dist/mcp/n8n-launcher.js`.

---

## Стадія 2. Уточнення параметрів у користувача (в чаті)

Запитайте у користувача два параметри конфігурації (якщо він ще не вказав їх у своєму повідомленні):

1. **Який агентський харнес (один або кілька) потрібно налаштувати?**
   - `antigravity` — **Google Antigravity** (створює локальний плагін `.agents/plugins/n8n-architect/`);
   - `codex` — **OpenAI Codex** (`.codex/config.toml`, `AGENTS.md`, `.agents/skills/`);
   - `claude-code` — **Claude Code** (`.mcp.json`, `CLAUDE.md`, `.claude/skills/`, `/n8n-build`);
   - `vscode-copilot` — **VS Code GitHub Copilot Agent Mode** (`.vscode/mcp.json`, `.github/copilot-instructions.md`, `/n8n-build`);
   - або `all` (усі одразу).
2. **Як підключаємося до інстансу n8n?**
   - **Варіант А (Існуючий сервер n8n)**: попросіть `N8N_API_URL` (наприклад, `http://localhost:5678` або `https://...n8n.cloud`) та запропонуйте або безпечно вписати `N8N_API_KEY` самостійно у файл `.env` (скопіювавши з `.env.example`), або передати для автоналаштування.
   - **Варіант Б (Локальний n8n через Docker)**: перевірте `docker --version`, запустіть `docker compose up -d`, підкажіть відкрити `http://localhost:5678`, створити ключ у **Settings -> n8n API** і додати його в `.env`.

Дочекайтеся відповіді користувача перед переходом до Стадії 3.

---

## Стадія 3. Генерація конфігурацій Харнесу та перевірка зв'язку з n8n

1. Запустіть CLI-ініціалізатор у неінтерактивному режимі відповідно до вибору користувача:
   - Якщо користувач вже заповнив `.env` самостійно:
     ```bash
     npm run init -- --harness <обрані_харнеси_через_кому> --use-existing-env
     ```
   - Якщо користувач надав URL та ключ у чаті:
     ```bash
     npm run init -- --harness <обрані_харнеси_через_кому> --n8n-url "<URL>" --n8n-key "<KEY>"
     ```
   - Якщо сервер n8n буде підключено трохи пізніше:
     ```bash
     npm run init -- --harness <обрані_харнеси_через_кому> --skip-n8n-check
     ```
2. Перевірте вивід команди: чи успішно пройшла перевірка Public REST API сервера n8n (`✔ З'єднання з n8n ... успішне!`) та чи створені конфігураційні файли обраного харнесу.

---

## Стадія 4. Фінальна перевірка MCP та готовність до роботи

1. Виконайте швидку перевірку парсера документів на демо-файлі:
   ```bash
   npm run parse-doc -- examples/lead-processing-spec.md
   ```
2. Повідомте користувачу підсумок:
   - Які конфігурації створено (нагадавши, що всі локальні конфіги та `.env` автоматично захищені від потрапляння в GitHub).
   - Як активувати щойно створені MCP-сервери (`n8n-mcp` та `doc-ingest`) у його поточному харнесі (перезапустити сесію чату / оновити MCP Servers).
   - Запропонуйте одразу надіслати посилання на Google Doc або покласти файл інструкції (`.docx`, `.doc`, `.md`, `.txt`) у папку `user-docs/`, щоб побудувати перший флоу!
