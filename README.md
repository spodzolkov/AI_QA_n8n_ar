# Multi-Harness n8n Flow Architect

Інфраструктурний проєкт на базі **MCP (Model Context Protocol)** та **агентських харнесів**, який підключається до вашого інстансу **n8n**, зчитує документи з інструкціями (відкриті посилання на **Google Docs**, файли **`.docx`**, **`.doc`**, **`.md`**, **`.txt`**), будує або модифікує воркфлоу в n8n та проводить структуроване уточнення вимог прямо в агентському чаті.

> **100% Harness-Native**: Проєкт не вимагає жодних зовнішніх API-ключів до LLM (OpenAI / Anthropic / Gemini) у коді. Весь інтелект, оркестрація та діалог працюють нативно у вибраному вами агентському харнесі.

---

## Підтримувані агентські харнеси

При ініціалізації проєкту можна обрати один або декілька харнесів одночасно:

| Харнес | Код у CLI | Що налаштовується автоматично |
| :--- | :--- | :--- |
| **Google Antigravity** | `antigravity` | Локальний плагін `.agents/plugins/n8n-architect/` (`plugin.json`, `mcp_config.json`, правила та скіл) |
| **OpenAI Codex** | `codex` | `.codex/config.toml`, `AGENTS.md`, скіл `.agents/skills/n8n-flow-builder/` |
| **Claude Code** | `claude-code` | `.mcp.json`, `CLAUDE.md`, скіл та slash-команда `/n8n-build` |
| **VS Code (GitHub Copilot)** | `vscode-copilot` | `.vscode/mcp.json`, `.github/copilot-instructions.md` та промпт `/n8n-build` |

## Швидкий старт (Скіл першого запуску `init`)

### Варіант А — Через агентський чат (Рекомендовано)
У свіжоклонованому репозиторії вже вбудований стартовий bootstrap-скіл **`init`** для всіх 4 харнесів:
1. Відкрийте папку проєкту у вашому харнесі (**Antigravity**, **Codex**, **Claude Code** або **VS Code Copilot**).
2. Напишіть у чаті `/init` (або *«Виконай перший запуск проєкту init»*).
3. Агент самостійно перевірить середовище, встановить усі npm-залежності, збере MCP-сервери, запитає ваш харнес та параметри підключення до n8n (або підніме локальний n8n у Docker) і протестує з'єднання.

### Варіант Б — Через інтерактивний термінал
```bash
npm install
npm run init
```

Або у неінтерактивному режимі:
```bash
npm run init -- --harness antigravity --n8n-url http://localhost:5678 --n8n-key <ВАШ_N8N_API_KEY>
```

## Як створити або змінити флоу за документом

1. Покладіть документ із вимогами (`.docx`, `.doc`, `.md`, `.txt`) у папку `user-docs/` **або** підготуйте посилання на відкритий для читання Google Doc (*Anyone with the link -> Viewer*).
2. Напишіть у чаті вашого харнесу (або викличте `/n8n-build`):
   - *«Створи воркфлоу в n8n за документом `user-docs/spec.docx`»*
   - *«Прочитай інструкцію `https://docs.google.com/document/d/.../edit` та онови існуючий флоу обробки замовлень»*
   - Для швидкого демо-тесту: *«Створи чернетку флоу за `examples/lead-processing-spec.md`»*
3. **Як діятиме агент**:
   - **Етап 1**: Зчитає документ через `doc-ingest` MCP та перевірить зв'язок із n8n. Якщо є критичні блокери до старту — уточнить їх одразу.
   - **Етап 2**: Звірить схеми нод через `n8n-mcp`, побудує валідну чернетку флоу безпосередньо на вашому сервері n8n (із підказками `Sticky Notes`), надасть пряме посилання на флоу та **поставить у чаті структуровані уточнюючі питання** щодо Credentials, бізнес-умов і межових випадків.
   - Після кожної вашої відповіді в чаті агент ітеративно доопрацьовуватиме флоу в n8n.

## Збереження чистого проєкту на GitHub (без користувацьких даних)

Проєкт має вбудований трирівневий захист, щоб ваші `.env` ключі, локальні шляхи машини (`Users/<username>`), згенеровані конфіги харнесів чи документи з `user-docs/` **ніколи** не потрапили на GitHub:

1. **Перевірити стерильність проєкту вручну**:
   ```bash
   npm run check:clean
   ```
2. **Очистити згенеровані конфігурації харнесів до стану чистого шаблону** (стартовий скіл `init` при цьому зберігається!):
   ```bash
   npm run clean:user-data
   # Щоб також видалити локальний .env та файли у user-docs/:
   npm run clean:user-data -- --all
   ```
3. **Опублікувати чистий проєкт на GitHub**:
   ```bash
   # Попередній перегляд списку файлів без коміту:
   npm run github:publish -- --dry-run

   # Публікація в існуючий репозиторій:
   npm run github:publish -- --remote https://github.com/<owner>/<repo>.git

   # Або автоматичне створення нового репозиторію через GitHub CLI (gh):
   npm run github:publish -- --repo n8n-multi-harness-architect --private
   ```

## Корисні команди розробника

- `npm run build` — компіляція TypeScript MCP-серверів у `dist/`
- `npm run parse-doc -- <шлях-або-URL>` — ручна перевірка читання документа з термінала
- `npm test` — запуск повного набору автотестів (парсери, адаптери 4 харнесів, сканер чистоти, JSON-RPC smoke-тести обох MCP-серверів)
