---

Проведіть користувача через повну ініціалізацію проєкту **Multi-Harness n8n Flow Architect** українською мовою:

Додаткові аргументи від користувача (якщо передані): $ARGUMENTS

1. Перевірте `node -v` (`>=20`). Якщо немає `node_modules/`, виконайте `npm install`. Потім обов'язково виконайте `npm run build`.
2. Запитайте користувача (якщо ще не вказано в аргументах):
   - Який харнес активувати: `claude-code`, `antigravity`, `codex`, `vscode-copilot` або `all`?
   - Підключаємося до існуючого інстансу n8n (`N8N_API_URL` + `N8N_API_KEY`, які можна вписати в `.env` або надати) чи піднімаємо локальний n8n командою `docker compose up -d`?
3. Виконайте генерацію конфігів:
   - `npm run init -- --harness <обрані> --use-existing-env` (або з `--n8n-url` / `--n8n-key` / `--skip-n8n-check`).
4. Повідомте про готовність, нагадайте оновити MCP-підключення (`/mcp` або перезапуск сесії) та запропонуйте протестувати `/n8n-build` на власному документі чи `examples/lead-processing-spec.md`.
