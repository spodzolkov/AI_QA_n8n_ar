# Скіл першого запуску проєкту (`init`)

Використовуйте цей скіл, коли користувач уперше відкрив або клонував репозиторій, викликав `/init`, або попросив розгорнути й налаштувати проєкт під свій агентський харнес та сервер **n8n**.

> **Важливо**: Проводьте користувача через стадії послідовно, українською мовою. Ніколи не виводьте значення `N8N_API_KEY` відкритим текстом у відповідях чату.

1. **Стадія 1 (Залежності та збірка)**: перевірте `node -v` (`>=20`), за відсутності `node_modules` запустіть `npm install`, після чого виконайте `npm run build`.
2. **Стадія 2 (Вибір опцій у чаті)**: запитайте користувача:
   - який харнес налаштувати (`antigravity`, `codex`, `claude-code`, `vscode-copilot` або `all`);
   - підключитися до існуючого сервера n8n (`N8N_API_URL` + `N8N_API_KEY` у `.env` або в чаті) чи запустити локальний n8n через `docker compose up -d` (`http://localhost:5678`).
3. **Стадія 3 (Запуск ініціалізатора)**: виконайте `npm run init -- --harness <обрані_харнеси> --use-existing-env` (або з `--n8n-url` та `--n8n-key`, чи `--skip-n8n-check`).
4. **Стадія 4 (Підтвердження)**: перевірте роботу парсера `npm run parse-doc -- examples/lead-processing-spec.md`, підкажіть перезапустити/оновити MCP-сервери у вибраному харнесі та запропонуйте передати перший документ ТЗ (посилання на Google Doc або файл `.docx`/`.doc`/`.md`/`.txt` у `user-docs/`).
